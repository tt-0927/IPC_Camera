# BLE 指令配网框架

## 生命周期

- `operation` 启动后通过 BlueZ 把 `hci0` 置为 `Powered=true`，注册 GATT 服务并持续广播。
- 广播名称为 `<设备型号>-<achSerialNumber>`。当前设备型号取 `MQTT_MODEL`，序列号取 `/proc/cpuinfo` 的 `Serial` 字段。
- 手机必须先下发 Wi-Fi 配置并确认 Wi-Fi 连接成功，再下发平台配置。
- Wi-Fi 成功后，设备每 10 秒查询一次平台连接状态。
- 平台连接成功后先向手机返回结果，3 秒后注销广播和 GATT 服务，并把适配器置为 `Powered=false`。
- 平台未连接或连接失败时，蓝牙保持开启，允许手机重试。

## GATT 结构

- Service: `7a1e0001-7d8b-4f31-9e45-545650524f56`
- Command（手机写）: `7a1e0002-7d8b-4f31-9e45-545650524f56`
- Response（手机读/订阅 Notify）: `7a1e0003-7d8b-4f31-9e45-545650524f56`

## 指令帧

所有多字节整数使用网络字节序：

| 字段 | 长度 | 说明 |
|---|---:|---|
| magic | 2 | 固定 `54 56`（TV） |
| version | 1 | 当前为 1 |
| flags | 1 | bit0 为响应帧 |
| command | 2 | 指令码 |
| sequence | 2 | 请求/响应关联序号 |
| payloadLength | 2 | 最大 1024 |
| payload | N | 指令数据 |
| crc16 | 2 | CRC16-CCITT，覆盖前面所有数据 |

响应帧 payload 的前两个字节是状态码，后面才是指令返回数据。异步连接结果沿用原请求的 command 和 sequence。

## 指令码

| 指令码 | 功能 | payload |
|---:|---|---|
| `0x0001` | 获取协议能力 | 空 |
| `0x0002` | 心跳 | 原样返回 |
| `0x0101` | 保存 Wi-Fi 凭据 | `WifiStaConncet_S` 对应 JSON |
| `0x0102` | 开始连接 Wi-Fi | 空；实际使用上一步保存的数据 |
| `0x0103` | 获取 Wi-Fi 配网状态 | 空 |
| `0x0104` | 取消配网 | 预留 |
| `0x0105` | 扫描附近 Wi-Fi | 认证后发送加密空业务数据；异步返回 SSID 和加密方式列表 |
| `0x0201` | 保存平台配置并连接平台 | `Platform_Info_t` 对应 JSON |
| `0x0202` | 获取平台连接状态 | 空 |
| `0x0300-0x6fff` | 后续公共蓝牙功能 | 按功能定义 |
| `0x7000-0x7fff` | 厂商扩展 | 按功能定义 |

状态查询返回文本为 `state=<值>;detail=<说明>`。Wi-Fi 状态：0 未配置、1 凭据就绪、2 连接中、3 已连接、4 失败；平台状态：0 未连接、1 连接中、2 已连接、3 失败。

## 手机侧完整流程

1. 扫描 `<设备型号>-<achSerialNumber>` 并连接设备。
2. 发现上述 Service，订阅 Response 特征值的 Notify。
3. 下发 `0x0101` 保存 Wi-Fi 凭据。
4. 下发 `0x0102` 连接 Wi-Fi，等待相同 sequence 的异步结果；也可用 `0x0103` 查询。
5. Wi-Fi 成功后下发 `0x0201` 配置并连接平台。Wi-Fi 未成功时该指令返回 `STATUS_BUSY`。
6. 等待平台连接结果，或使用 `0x0202` 查询状态。
7. 收到平台成功结果后，设备会在 3 秒后关闭蓝牙；手机应主动断开并结束配网界面。

长帧可按顺序多次写入 Command 特征值，设备端解码器会完成粘包、拆包和 CRC 校验。

## 安全说明

当前框架已经隐藏设备日志中的 Wi-Fi/平台敏感 payload，但 GATT 业务层尚未加入会话认证、应用层加密、随机数和防重放机制。正式产品不应在未配对、未加密的 BLE 链路上明文传输 Wi-Fi 和平台密码。
