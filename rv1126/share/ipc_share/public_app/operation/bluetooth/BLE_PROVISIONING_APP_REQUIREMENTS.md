# BLE 配网 App 功能需求

本文是 BLE 配网 App 的简要功能需求，详细报文、指令码、加密算法和测试向量参见 `BLE_PROVISIONING_PROTOCOL.md`。

## 1. 设备二维码

- 支持扫描设备二维码。
- 解析并保存二维码中的协议版本、设备型号、序列号、Service UUID 和 `setupSecret`。
- 校验二维码字段是否完整、格式是否合法。
- `setupSecret` 仅保存在当前配网流程中，不写入日志、埋点或明文持久化文件。

## 2. 蓝牙设备发现

- 按 Provisioning Service UUID 扫描 BLE 设备。
- 显示扫描到的设备名称和信号强度。
- 使用二维码中的型号、序列号与广播名称匹配目标设备。
- 不依赖 BLE MAC 地址匹配设备。
- 支持扫描超时、重新扫描和用户取消。

## 3. BLE 连接与初始化

- 连接目标设备并发现配网 Service、Command 和 Response 特征。
- 连接成功后优先申请较大的 MTU；实际通信使用系统最终协商结果。
- 订阅 Response Characteristic 的 Notify，订阅成功后才允许发送指令。
- 使用 `0x0001` 查询并校验设备协议版本及安全能力。
- 支持 BLE 连接超时、断开提示和重新连接。

## 4. 安全认证

- 使用二维码中的 `setupSecret` 完成 `0x0010`、`0x0011` 认证流程。
- 使用安全随机数生成 `appNonce`。
- 按协议计算 HMAC-SHA256 Proof 和临时 `sessionKey`。
- 认证成功前禁止发送 Wi-Fi、平台等敏感业务指令。
- 支持使用 `0x0012` 查询认证状态。
- 每次 BLE 重连后清除旧会话，并重新认证。
- 正确维护 AES-GCM nonce 和防重放 counter；不得复用旧值。

## 5. Wi-Fi 扫描与选择

- 通过 `0x0105` 发起 Wi-Fi 扫描。
- 区分扫描“已受理响应”和“最终扫描结果”。
- 解析设备返回的 `count`、`truncated`、`ssid` 和 `security`。
- 显示开放、WEP、WPA、WPA2、WPA3 等加密类型。
- 支持中文及其他 UTF-8 Wi-Fi 名称的正确显示。
- `truncated=true` 或未扫描到目标网络时，允许用户手动输入 SSID。
- 支持扫描超时、失败提示和重新扫描。

## 6. Wi-Fi 信息输入

- 支持输入或选择 SSID。
- 支持输入 Wi-Fi 密码，并提供显示/隐藏密码功能。
- 根据网络加密方式生成正确的 `mode`、`pairwise` 和 `wpa3Type`。
- 开放网络允许不输入密码。
- SSID 统一使用 UTF-8，不使用 GBK 或十六进制显示文本。
- 按 UTF-8 字节数校验 SSID 长度为 1～32字节，而不是按字符数量校验。
- 拒绝非法 UTF-8、NUL 字符和超过32个 UTF-8 字节的 SSID。

## 7. Wi-Fi 连接

- 将 Wi-Fi 凭据序列化为紧凑 UTF-8 JSON。
- 使用认证会话对业务 JSON进行 AES-256-GCM加密。
- 通过 `0x0101` 保存 Wi-Fi 凭据。
- `0x0101` 成功后通过 `0x0102` 发起连接。
- 区分连接“已受理响应”和“最终连接结果”。
- 支持通过 `0x0103` 查询 Wi-Fi 状态。
- 只有确认 Wi-Fi 状态为 `state=3` 后，才进入平台连接步骤。
- 对密码错误、找不到网络、认证失败、连接超时等情况给出清晰提示。

## 8. 平台连接

- 提供平台地址、端口、用户名、密码及其他必要参数的输入或预置能力。
- 使用认证会话加密平台连接参数。
- Wi-Fi 连接成功后，通过 `0x0201` 发起平台连接。
- 区分平台连接“已受理响应”和“最终连接结果”。
- 支持通过 `0x0202` 查询平台连接状态。
- 只有平台状态为 `state=2` 时，才显示完整配网成功。
- 配网成功后设备主动关闭 BLE造成的断开应识别为正常流程。

## 9. BLE 分包发送

- 先生成完整协议帧，再按照系统提供的最大写入长度进行分片。
- 分片只包含完整帧的连续原始字节，不增加额外帧头、长度、序号或 CRC。
- 所有请求使用统一的串行发送队列，禁止两条请求的分片交错。
- 优先使用 Write With Response。
- 每一片收到写成功回调后才发送下一片。
- 完整帧发送完成后再开始等待协议响应。
- 某片写失败时停止剩余分片，不允许只重发失败片。

## 10. Notify 接收与组帧

- 每条 BLE 连接维护独立的二进制接收缓存。
- 每次 Notify 只作为一个字节片段追加，不能直接当作完整响应解析。
- 根据协议头的 `Payload Length` 计算完整帧长度：`12 + Payload Length`。
- 收齐完整帧后校验 Magic、Version、Flags、长度和 CRC16。
- 支持一次缓存中连续解析多条完整响应。
- 帧头错误时逐字节重新搜索 `54 56`。
- CRC、长度或 UTF-8 JSON解析失败时丢弃坏帧，不影响后续帧。
- 中文字符跨 Notify 分片时，必须在完整组帧后统一进行 UTF-8解码。

## 11. 请求与响应管理

- 为每个新请求生成递增的 `sequence`。
- 使用 `(command, sequence)` 匹配请求和响应。
- 支持一个异步指令返回“受理”和“最终结果”两条响应。
- 收到未知 sequence 时记录并忽略，不能完成其他请求。
- 对普通指令、认证、Wi-Fi 扫描、Wi-Fi 连接和平台连接分别设置合理超时。
- 最终响应超时后优先使用状态查询，不要盲目重复提交敏感配置。

## 12. 异常恢复

- BLE 断开时清空接收缓存、发送队列、pending 请求和认证会话。
- 请求分片写失败后，可等待超过5秒再使用新 sequence 整帧重发。
- 也可以断开并重新连接、订阅、认证后重新发送。
- Notify 响应组帧超时后清空本地接收缓存。
- 响应超时时可 Read Response Characteristic，尝试读取设备缓存的最后完整响应。
- Read 到的 command、sequence 不匹配时不能作为当前请求结果。
- 处理未认证、认证失败、认证锁定、重放检测、设备忙和内部错误等状态码。

## 13. 页面和交互

- 至少包含二维码扫描、设备搜索、Wi-Fi 选择、密码输入、平台配置、配网进度和结果页面。
- 配网过程中显示当前阶段：发现设备、连接 BLE、认证、扫描 Wi-Fi、连接 Wi-Fi、连接平台、完成。
- 允许用户取消未完成的配网流程。
- 错误提示应给出可操作建议，例如重新扫描、检查密码、靠近设备或重新认证。
- 不向普通用户显示密钥、密文、CRC 等底层调试数据。

## 14. 安全和隐私

- Wi-Fi 密码和平台密码必须通过安全会话加密传输。
- 不记录 `setupSecret`、`sessionKey`、Proof、完整 nonce、Tag、密文或用户密码。
- 敏感输入不进入统计、崩溃上报、剪贴板或截图缓存。
- 配网结束、取消、超时或 App 进入不可恢复状态时及时清除内存中的敏感数据。
- 广播名称只能用于设备匹配，敏感指令必须依赖二维码密钥认证。

## 15. 最低验收项目

- 能通过二维码准确找到并连接指定设备。
- 能完成认证、Wi-Fi 扫描、Wi-Fi 连接和平台连接完整流程。
- 能连接英文、中文及混合字符 SSID。
- MTU=23 时，长请求和 Wi-Fi 扫描长响应能够正确分包、组包和校验。
- 人为制造分片失败、CRC 错误、超时和 BLE 断开后能够恢复。
- 重连后旧认证会话不能继续使用。
- 配网成功后设备主动关闭 BLE，App 能正确显示成功而不是报连接异常。
- 日志和错误上报中不存在任何密钥或密码明文。
